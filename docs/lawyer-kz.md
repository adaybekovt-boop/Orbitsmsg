# Ticket: нужен юрист РК (Phase E)

Это **не** задача на написание кода и **не** черновик оферты от модели.
Нужен юрист в Казахстане, знакомый с законом РК «О персональных данных»
и профильным регулированием. Текст оферты / политики пишет юрист.
Реализация в приложении — второй шаг, после получения текста.

Не вставлять в продукт сгенерированные «юридические» формулировки.

## Зачем тикет

Публичный продукт (мессенджер Orbits) сейчас не имеет идентифицируемой
оферты с реальным субъектом и честным описанием того, что происходит
с данными. Маркетинг и UI не должны подменять этот документ.

## Что юрист должен решить (вопросы, не ответы)

1. Кто является оператором / субъектом оферты (ИП / ТОО / физлицо) и какие
   контактные данные можно и нужно публиковать.
2. Нужна ли публичная оферта, политика ПДн, согласие, возрастной порог
   (18+ или иной по локальному праву), и в какой форме.
3. Как описывать отсутствие серверов хранения контента **без** ложных
   фраз про «серверы Владельца», если таких серверов нет.
4. Как описывать третьи стороны: PeerJS signaling, Google/Mozilla/Twilio
   STUN, возможный TURN, GitHub Releases (обновления).
5. Обязанности по жалобам / блокировке / хранению репортов — минимум,
   который закон требует от такого P2P-клиента.

## Техническое ТЗ на продукт (делать ПОСЛЕ текста юриста)

1. Экран/раздел с реальной офертой: идентифицируемый субъект и контакты
   в рамках того, что разрешит юрист. Без заявлений о «серверах Владельца»,
   если серверов хранения контента нет.
2. Кнопка/форма «Пожаловаться»: локальная блокировка + сохраняемый репорт
   (peer id + опциональное описание), который пользователь может переслать
   (email / Issues / контакт из оферты). Бэкенд-модерация с нуля не
   требуется, но одной только локальной блокировки недостаточно.
3. Возрастное ограничение (18+ или то, что скажет юрист) на экране
   регистрации, не только в тексте оферты.
4. Честное описание данных: IP на TURN/сигналинге третьей стороны, peer id
   локально, отсутствие контента переписки на серверах Orbits.

## Чего в этом тикете нет

- Готового текста оферты, политики, дисклеймеров.
- Изменения LICENSE / решения «open source vs proprietary» (это отдельное
  решение владельца + юриста; см. `docs/landing-honesty.md`).
- Готового текста оферты (экраны в приложении — заглушки с
  `[TEXT PENDING LEGAL REVIEW]`, см. Round 3 C).
